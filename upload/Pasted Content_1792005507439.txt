# Stayora Host Dashboard — Complete Features, Pages & Functions

Based on your uploaded Airbnb screenshots, this continuation focuses specifically on the host side: creating a property listing, managing it after publication, handling Today's tasks, Messages, Edits, Verifications, and the complete listing creation wizard through Step 8 and beyond.

The screenshots show several important Airbnb workflows: the host Listings dashboard, account settings, property type selection, location pin placement, guest capacity, amenities, photo uploads, title and description, safety disclosures, pricing, discounts, booking settings, and final publication.

For Stayora, these should be implemented as functional pages with saved data, validation, real actions, and clear progress—not just as static screens.

- View reservation details by selecting a booking.
- Import or export external calendar feeds where supported.
- See synchronization errors and resolve conflicts.

### Calendar status indicators

| Status      | Display and behavior                                    |
| ----------- | ------------------------------------------------------- |
| Available   | Accept eligible bookings                                |
| Reserved    | Show the existing reservation                           |
| Blocked     | Prevent new bookings                                    |
| Pending     | Apply the configured temporary reservation rules        |
| Unavailable | Prevent bookings due to restrictions or inventory rules |
| Sync issue  | Show a warning and offer recovery actions               |

### Required validation

1. The host cannot accidentally overwrite an existing confirmed booking.
2. A date-range price update must preserve unrelated date overrides.
3. Blocked dates must be excluded from search availability.
4. Calendar updates must be persisted to the backend.
5. External calendar synchronization must not be treated as infallible.
6. Concurrent booking attempts must be resolved by server-side inventory controls.

### 6.2 Editing behavior

- Load existing saved values into every field.
- Show the last-saved state.
- Save changes without accidentally resetting other sections.
- Support explicit Save and Cancel actions.
- Validate required fields before saving or publishing.
- Display field-level errors and actionable messages.
- Warn about unsaved changes before navigating away.
- Keep draft edits when the user returns later.
- Preview the listing before applying changes to the public version.
- Record the editor, changed fields, and timestamp.
- Allow authorized co-hosts to edit only permitted sections.
- Maintain the published listing if a draft edit is incomplete.
- Apply changes to the public listing only according to the chosen save/publish model.

### 6.3 Important edit restrictions

- Changing the address may trigger location or compliance revalidation.
- Reducing capacity must not invalidate existing confirmed reservations without an appropriate resolution.
- Changing nightly prices must not silently alter a confirmed booking's agreed price.
- Changing cancellation rules must not retroactively override the policy attached to existing bookings.
- Editing photos must not break existing image references or public listing URLs.
- Changing safety disclosures must update the public safety information and audit history.

## 8. Create a listing — complete wizard, including Step 8

The listing creation experience should be a multi-step wizard. Hosts must be able to move backward, save progress, resume later, and see which requirements remain.

The following is the recommended Stayora sequence based on your screenshots and the Airbnb-inspired workflow.

### 1

### Choose property type

Select an entire place, private room, shared room, or other supported accommodation type. Then select the specific property category, such as house, apartment, cabin, villa, guesthouse, or unique stay.

### 2

### Set property location

Enter the country, address, city, region, postal code, and map position. Configure whether the guest sees an approximate or precise location before booking.

### 3

### Share property basics

Set maximum guests, bedrooms, beds, bathrooms, sleeping arrangements, and other capacity details.

### 4

### Add amenities and safety equipment

Choose Wi-Fi, kitchen, air conditioning, parking, pool, workspace, accessibility features, smoke alarms, carbon monoxide alarms, and other applicable facilities.

### 5

### Upload property photos

Upload and reorder images, choose a cover image, organize room photos, add captions, validate image quality, and remove duplicates.

### 6

### Create title and description

Enter a short property title, choose suitable highlights, write a detailed description, and preview how the listing will appear.

### 7

### Add safety details and house rules

Disclose exterior cameras, noise monitors, weapons, and other required safety information. Configure smoking, parties, pets, quiet hours, check-in/out, and occupancy rules.

### 8

### Configure availability and booking settings

Set the booking window, minimum and maximum nights, blocked dates, preparation gaps, check-in restrictions, reservation approval mode, and any supported instant-book eligibility.

### 9

### Set nightly prices and discounts

Configure the base price, weekend and seasonal adjustments, weekly/monthly discounts, promotions, cleaning fees, and applicable charges.

### 10

### Complete host and payout verification

Provide required contact information, identity and address verification, payout setup, and tax information where required.

### 11

### Review and publish

Validate all sections, preview the public listing, resolve missing requirements, confirm the applicable policies, and publish or save the draft.

### Wizard navigation functions

Every step should support:

- Back.
- Next.
- Save and exit.
- Save draft automatically where appropriate.
- Progress indicator.
- Validation messages.
- Resume from the last completed section.
- Skip optional fields where permitted.
- Help and contextual explanations.
- Listing preview where applicable.
- Unsaved-change protection.

A listing should not be published just because the host reaches the final step. Publication must depend on required information, eligibility, applicable verification, and moderation requirements.

### Step 8 backend rules

- Reject invalid minimum and maximum stay combinations.
- Calculate eligible check-in dates using the booking window and advance notice.
- Apply preparation gaps to calendar availability.
- Apply arrival and departure restrictions to the correct local dates.
- Revalidate all settings against existing confirmed bookings.
- Require Instant Book eligibility before enabling automatic confirmation.
- Keep booking requests separate from confirmed reservations.
- Record changes to booking settings.
- Recalculate search availability after the settings change.
- Ensure a host cannot make dates unavailable in a way that silently invalidates confirmed reservations.

## 15. Final implementation requirements

To make all of these pages work together, Stayora needs:

1. Persistent data: Listings, drafts, edits, calendars, messages, verification records, and settings must be saved in the database.
2. Role-based permissions: Guests, hosts, co-hosts, and administrators must see only the actions and information they are authorized to access.
3. Shared listing data: The wizard, listing editor, public property page, calendar, and admin panel must use the same underlying listing record.
4. Verification integration: Store verification statuses and provider references securely.
5. Real messaging: Persist conversations and messages; do not use hardcoded sample conversations in production.
6. Reliable booking logic: Prevent conflicting reservations and preserve confirmed booking terms.
7. Consistent status management: Update the Listings page, Today page, calendar, and notifications when a booking or listing changes.
8. Responsive UI: Support desktop, tablet, and mobile screens.
9. Accessible forms: Use clear labels, keyboard navigation, field-level errors, and appropriate focus management.
10. Audit and recovery: Record important changes and support safe retries after network or provider failures.

Recommended build order: Start with the listing wizard and Step 8 settings, then implement listing editing, verification, the Today page, Messages, calendar, and reservation management. Once these workflows are connected to persistent data and tested end to end, expand the host dashboard with payouts, analytics, co-hosting, and advanced tools.
